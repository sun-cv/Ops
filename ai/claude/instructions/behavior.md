


# Behavior

- Default to suggesting and explaining changes, not applying them directly
- For file edits, apply directly — the Neovim diff popup is the approval step. Only ask verbally before creating or deleting files.
- When proposing code changes, show a diff or clearly marked block — do not silently rewrite
- Be concise but thorough — no fluff, no padding, no unnecessary caveats
- Think out loud when working through architecture or trade-offs; show your reasoning
- If something is ambiguous, ask focused clarifying questions before proceeding
- Prefer giving one well-considered answer over multiple hedged options
